# galois — motivic Galois coaction engine + exact MZV relation ring

`galois` does two related things, exactly and over Q:

1. **Coaction cuts.** It computes the motivic Galois derivations D_m
   (Goncharov coproduct) on multiple zeta values, H-function words, and Brown's
   single-valued HPLs, and turns coaction stability — the requirement that the
   Galois derivatives of a fitted combination land in the span generated by
   already-solved family members — into exact homogeneous linear constraints on
   the coefficients of a polylog ansatz. Each annihilator functional of the
   allowed span is one exact row, gained at zero boundary-data cost.
2. **MZV relation ring** (`galois.mzvring`). Exact double-shuffle
   canonicalization of `{zeta(n), mzv(a,b), mzv(a,b,c)}` monomials over Q,
   depth ≤ 3, weight ≤ 23, with no PSLQ anywhere: per-weight Gauss elimination
   whose survivors reproduce the Broadhurst–Kreimer depth ≤ 3 dimensions
   (e.g. 8 at weight 23).

**Disambiguation.** "Galois" here means the *motivic* Galois coaction (cosmic
Galois, F. Brown) — not differential Galois groups, and not the unrelated PyPI
`galois` finite-field library (see the name-collision note below).

**Status of the coaction principle.** Coaction stability is a conjectural
constraint (verified to 11 loops in phi^4 and in production use in the hexagon
bootstrap program). Rows produced here are ansatz-cutting input; any result
built with them still needs the usual exact solve and independent held-out
verification.

## Package layout

- `core` — Goncharov-coproduct derivations D_m (m = 3, 5, 7) on
  shuffle-regularized MZVs (polynomials over pi^2, z3, z5, z7, z53), on
  H-function words at generic argument, and on Brown svHPLs via formal sv
  T-tables; exact sv-space decomposition (`SVDecomposer`); the conjugation
  matrix; ansatz-element conversion in the I[z,w,0]/f-token conventions
  (I[z,w,0] = (-1)^{#1s} calL_w; f3/f5/f7/f33/f53 tokens).
- `vspace` — allowed-space machinery: parses solved-result ancillary files
  (Mathematica syntax; skips FAIL / epsilon / extended-alphabet entries),
  saturates the span under D3/D5/D7 (Galois closure), and exposes
  weight-and-parity fibers with exact annihilator functionals
  (`fiber_annihilator`).
- `sector21` — D_m for odd m = 3..19, plus the sv projection, on depth ≤ 3
  odd-index MZVs at odd weights 11..21, using the relation ring as its
  reduction oracle in place of the weight ≤ 8 tables.
- `svmap21` — the *algebraic* single-valued map: zeta_sv of depth ≤ 3
  odd-index MZVs (w ≤ 21) as exact formulas — Brown's sv projection on the
  f-alphabet (arXiv:1309.5309 §7.2, eq. (7.3)) with a trailing-strip
  orientation transport (orient B), and an exact rectangular phi^{-1} solve
  over the ring basis. Targets that need depth ≥ 4 content fail hard, never
  smoothed. `svmap21.py selftest --receipt PATH` writes a validation
  receipt on full PASS (nothing is written on failure).
- `mzvring` — the relation-ring subpackage:
  `from galois import mzvring; R = mzvring.load_ring(path)`, then
  `R.cvec / R.cmono / R.csym` canonicalize, `R.survivors[w]` gives the
  per-weight basis. Fresh tables:
  `python3 tools/galois/mzvring/build_ring.py --wmax N --out X.pkl
  [--resume PKL] [--checkpoint]`.

## Installation and data

The package is plain Python: `python3` + `sympy` + `mpmath` (plus `gmpy2` for
the ring eliminations). Single-core; the coaction engine stays under 1 GB RSS
and the ring under 100 MB through wmax = 23. Put this repository's `tools/`
directory on `sys.path` (or `PYTHONPATH`) and import:

```python
from galois import core, vspace, sector21, svmap21, mzvring
```

**Name collision.** PyPI ships an unrelated `galois` (finite-field) library.
With this repo's `tools/` directory ahead of site-packages on `sys.path`,
`import galois` resolves to this package. If you need both, import the PyPI
one first or load it by explicit file path.

**Reference data.** The package's table banks are not shipped in this
repository. Every entry point that needs them fails closed with a named error
telling you which environment variable to set; all entry points also accept
explicit paths:

- `GALOIS_RING_BANK` — directory of ring pickles. Build your own with
  `build_ring.py`: roughly 30 minutes at wmax = 21 and 2 hours at wmax = 23 on
  a single core. Pass `--checkpoint` to dump `<out>.partial` after every
  weight.
- `GALOIS_T0DEEP` — directory holding the weight ≤ 8 MZV/sv table bank
  (`mzv_formal.py`, `mzv_tables_w8.json`, `svt_tables_w8.json`).
- `GALOIS_CAMPAIGN_BANK` — table root with subdirectories `galois/`
  (sector tables) and `svalign/` (sv formula and numeric banks).
- `GALOIS_ANC_DIR` — the solved-feed directory: the published ancillary files
  of arXiv:2607.11645, publicly downloadable.

What runs from a cold clone with no data: the pure ring algebra
(shuffle/`znorm` smokes) and `build_ring.py` fresh builds. Everything else
runs once you build or point the banks per the list above.

**MZV convention throughout:** `mzv(a1,..,ak) = sum_{m1>m2>..>mk>=1}
prod mi^{-ai}` — outer index first, a1 ≥ 2; even zetas reduce as
`zeta(2k) -> rational * pi2^k`.

## Usage

Coaction rows for an ansatz cut:

```python
from galois import core, vspace
vecs = vspace.collect_feed(...)          # parse solved family members
fibs = vspace.saturate(vecs)             # Galois closure, weight+parity fibers
F = vspace.fiber_annihilator(fib, wt, par)
# rows = functional . D_m(ansatz-element images), one per functional per block
```

Outputs are exact `Fraction` rows `{col: q}` (homogeneous, right-hand side 0),
labeled `coact:b<off>:D<m>w<wt>:f<i>`.

Derivations directly: `core.Dm_zpoly(zp, m)`, `core.Dm_hword(u, m)`,
`core.Dm_calL(word, m)`, `core.Dm_vector(vec, wt, m)`; conjugation via
`core.conj_vector(vec)`.

Ring canonicalization:

```python
from galois import mzvring
R = mzvring.load_ring(path)   # or set GALOIS_RING_BANK
v = R.csym(('m2', 5, 3))      # canonical form of mzv(5,3)
R.survivors[8]                # the depth<=3 basis at weight 8
```

Symbols: `('pi2',)` = pi^2, `('z', n)` for odd n ≥ 3, `('m2', a, b)`,
`('m3', a, b, c)`. Vector algebra: `dsum/dscale/dmul`; words:
`comp_word/word_comp/shuffle`.

Command-line entry points:

```
python3 tools/galois/sector21.py  selftest|gates|oracle|sector|sv  [--ring PKL --tables JSON --receipt J]
python3 tools/galois/svmap21.py   selftest|derive  [--ring PKL --svalign DIR --dps N --comps ...]
python3 tools/galois/mzvring/build_ring.py --wmax N --out X.pkl [--resume PKL] [--checkpoint]
```

A worked coaction datum, in this package's right-strip deconcatenation
convention `(id ⊗ pi_m) Delta`:
`D5 zeta(5,3) = -5 zeta3`, `D3 zeta(5,3) = 0`, `D7 zeta(5,3) = 0`
(matching the classical −5).

## Verification

The package was validated against the following batteries (counts as
measured; the receipts themselves are not included in this repository —
`svmap21.py selftest --receipt PATH` regenerates the svmap21 receipt against
your own bank):

- **Coaction engine.** G1: Goncharov D_m equals the double-shuffle Leibniz D_m
  on all 510 words × 3 derivations (1530 checks, 0 mismatches). G2:
  sv-closure — D_m(calL_w) decomposes exactly in the lower-weight sv space for
  every word (939 nonzero images, 0 failures), reproducing Brown's
  sv-stability in these conventions. G3: 135 odd + 169 even weight-8
  published ansatz lists are exact −1/+1 eigenvectors of the derived
  conjugation (sign and f-token conventions lock). G4: independent numeric MZV
  oracle at two precisions. G5, positive control: a solved family member's
  odd+even pure functions are coaction-stable against an allowed space built
  *without* that member (0/32 functionals violated), while planted
  single-element perturbations violate (6/135 odd, 119/169 even). A further
  archive certification ran 161 exact-Q items across 8 families: 0/161
  coaction violations, 4/4 planted perturbations caught.
- **Ring.** Broadhurst–Kreimer depth-3 dimensions reproduced by fresh
  per-weight elimination (w = 19: 5, w = 21: 6, w = 23: 8); 1298/1298 checks
  against 150-digit numerics.
- **sector21.** Selftest: 255 values + 765 D-images agree exactly with the
  core table route; 6 literature values (Brown arXiv:1102.1310/1102.1312,
  arXiv:2511.15883); 6 independent 200-digit FORM spot checks (minimum 196.4
  matching digits); identity, parity, and reversal locks.
- **svmap21.** Pin: 4 literature phi locks + Brown's printed eq. (7.3) depth-3
  example verbatim + sv(f2) = 0. Depth 2: all 27 all-odd depth-2 pairs against
  an independent 460-digit sv bank (minimum 480.7 matching digits), plus the
  exact lock `zeta_sv(5,3) = -10 z3 z5`. Regression: 61/61 reference sv
  formulas reproduced exactly under orient B (orient A gets only the 2/61
  palindromic keys — see the caveats). Extension: 22/22 algebraically derived
  keys match in-process re-derivation.

Re-run `sector21.py selftest` and `svmap21.py selftest` after any local
change; both write JSON receipts via `--receipt`.

## Caveats

- The allowed space V is exactly as strong as its solved feed. Rebuild V, and
  re-run the leave-one-out control, whenever new family members get solved. A
  failing leave-one-out control means V is too small — enlarge the feed with
  more solved siblings; never hand-patch fibers.
- Build V from independently published solved results only; never feed it
  candidate solutions you intend to test with it.
- Extended-alphabet integrals live outside the {0,1} sv space: the feed parser
  skips their blocks, so V is conservatively small on families where they
  matter.
- Convention traps are locked by G3 and the sector21 gates: if you change
  word or f-token conventions upstream, re-run the batteries before trusting
  any row. pi_m for m ≥ 11 is basis-dependent — it is pinned to the ring's
  survivor basis.
- **svmap21 orientation pin.** Brown's verbatim eq. (7.3) is written in the
  prefix-strip f-model (orient A); this package's f-model is trailing-strip,
  so the correct transport is orient B (reversal on the left deconcatenation
  factor), pinned empirically at 61/61 vs 2/61. A and B agree at depth ≤ 2 and
  on palindromic keys, so shallow checks cannot adjudicate between them —
  never "fix" an sv mismatch by flipping the orientation; re-run the 61-key
  regression instead.
- The ring is depth ≤ 3-truncated: expressions needing depth ≥ 4 content raise
  a hard error rather than being approximated. Elimination keeps the
  lexicographically largest all-odd no-1 arguments as survivors (`m2(5,3)`
  survives at w = 8); for a different basis convention, re-derive — never
  post-rotate canonical tables by hand.
- `csym` on an unknown symbol returns it as a basis vector rather than
  erroring; coverage discipline is the consumer's responsibility
  (`sector21.sym_vec` hard-stops on unknowns — do the same).
- Rebind rings via `svmap21.init_ring(path)`, not `sector21.init_ring` — the
  phi/monomial caches are ring-keyed and cleared only by the former.
- `load_ring` skips `__init__`; calling `Ring(wmax)` directly triggers a full
  rebuild. Ring pickles are the expensive artifact: never regenerate over an
  existing one in place — build to a new path, validate, then swap.
- Not for: alternating/Euler sums, elliptic families, depth ≥ 4 MZVs, or
  numeric evaluation (this package is exact-only).

## Background and attribution

The coaction principle is Francis Brown's [BrCG], sharpened by Erik Panzer and Oliver
Schnetz [PS] and, for amplitudes, by Caron-Huot, Dixon, Dulat, von Hippel, McLeod and
Papathanasiou [CDDvHMP]; the coproduct is Goncharov's [Gon] in Duhr's formulation
[Duhr12]; motivic decomposition and the f-alphabet follow Brown [BrDec, BrMTM];
single-valued MZVs/HPLs and the sv map follow Brown [BrSV] §7.2; conventions follow
Xuhang Jiang [Jiang]; the relation ring uses the regularized double-shuffle framework of
Ihara, Kaneko and Zagier [IKZ], Hoffman's relations [Hoffman] and the Broadhurst–Kreimer
depth-graded dimensions [BK]; literature checks against Brown [BrDec] and Schlotterer,
Sohnle and Tao [SST25]; 200-digit spot checks by FORM [FORM4]. Bracketed keys resolve in
REFERENCES.md at the repository root.
